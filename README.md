# Chronometer

Highly customizable date and time display with background images

[Official Collection on Unsplash](https://unsplash.com/collections/fYpR_W_NzKA/chronometer)

## Development

Use pnpm, with the version specified in `package.json`. `devEngines.runtime` declares
Node.js 24 for project tools. Run `pnpm install` to install dependencies and resolve
the managed runtime, and commit the resulting lockfile changes. Run project tools
through pnpm; `pnpm exec node --version` reports the project runtime.

```sh
pnpm install
pnpm dev
```

Open the local URL printed by Vite, under `/chronometer/`. The application still
uses the production photo API during local development.

Build the site and preview the production output with:

```sh
pnpm build
pnpm preview
```

Vite writes the built site to `dist/`, which is ignored by Git. `vite.config.ts`
sets the base path to `/chronometer/` for the repository's GitHub Pages URL. Update
that setting if the site moves to a custom domain or a different repository path.

`idb` is installed through pnpm and bundled by Vite. Photo history uses the
existing `chronometer-photo-history` IndexedDB database and schema version 1.

Application code lives in `src/`: `main.ts` is the entry point, `style.css` holds
the styles, and `assets/` contains the SVG and icons. `index.html` stays at the
repository root and references these files for Vite to process.

## Type checking

The application uses TypeScript with strict checking, including checks for missing
array elements. Run the compiler without emitting JavaScript with:

```sh
pnpm typecheck
```

`tsconfig.json` references separate projects for browser code (`tsconfig.app.json`)
and the Vite configuration (`tsconfig.node.json`). This keeps browser and Node.js
globals scoped to their respective environments. Vite transpiles TypeScript for
development and production; it does not run type checking, so CI runs this command
separately.

## Formatting

Oxfmt uses its defaults, configured by `.oxfmtrc.json`. This includes a print width
of 100 and automatic `package.json` field sorting. The configuration's local JSON
schema provides editor validation, completion, and hover documentation.

After installing dependencies with `pnpm install`, run:

```sh
pnpm format
pnpm format:check
```

`format` rewrites supported files; `format:check` checks formatting without changing
files. `ignorePatterns` in `.oxfmtrc.json` excludes the generated pnpm lockfile;
Oxfmt also respects `.gitignore`, including `dist/` and `node_modules/`. For VS Code,
use the Oxc extension and select Oxfmt as the formatter for supported languages.
See [Oxfmt's editor setup guide](https://oxc.rs/docs/guide/usage/formatter/editors.html)
for format-on-save configuration.

## Linting

Oxlint uses the default configuration generated by `oxlint --init` in
`.oxlintrc.json`, with `options.typeAware` enabled and `oxlint-tsgolint` installed.
Correctness rules are enabled as errors, including type-aware rules such as
`typescript/no-floating-promises`, so findings fail CI.

```sh
pnpm lint
pnpm lint:fix
```

`lint` reports issues without changing files. `lint:fix` applies available safe
fixes; review the changes and run `pnpm format` afterward if needed. The Oxc VS Code
extension detects the installed Oxlint and config for editor diagnostics. Type-aware
linting complements `pnpm typecheck`; both commands are required.

## Deployment

The GitHub Actions workflow runs formatting, type, and lint checks alongside builds on
pushes, pull requests, and manual runs. The `build` job uploads `dist/` as the Pages
artifact only for `main`. After both `checks` and `build` pass, the `deploy` job
publishes that artifact only for `main`. It deploys the same output that passed
the build, without rebuilding.
